Desk Technical Design

How the desk processes information, how it stores time-bounded data so a backtest can never peek at the future, how each LLM call is built so the expensive part is read from cache, and what a day costs in tokens. The HLD is one diagram; the LLD is the six that follow. The companion document is docs/04-technical-design.md.

HLD · how information is processed

Every fact, whether a price bar, a filing or a headline, passes through the same seven stages. The cold path may take minutes and may call an LLM. The hot path runs bar by bar in memory and never does.

LLD · time-bounded storage

One rule governs every table: a fact carries a valid time, when it was true in the world, and a knowledge time, when the desk could have known it. Every read that feeds a decision or a backtest is "as of knowledge time T".

LLD · the bus and the replayer

One Redis stream per topic. Each agent is a consumer group, so instances share work and every agent sees every event. The persister writes to PostgreSQL, which is the system of record. The replayer feeds history back onto the same streams under a simulated clock.

Idempotency rules
  • ULID event ids, time-sortable and unique
  • natural unique keys such as (symbol, interval, ts) with ON CONFLICT DO NOTHING
  • explicit XACK after the handler commits
  • pending entries reclaimed with XAUTOCLAIM after a crash
  • dead-letter stream after three failed deliveries, with an alert
  • every handler tolerates seeing the same event twice
Replay is the backtesterSELECT from events ordered by occurred_at, publish onto the same streams, advance the SimClock. Agents run unchanged. The execution adapter becomes the simulated broker. LLM calls hit the output cache, so replaying a month costs nothing in tokens unless a prompt changed.

LLD · how the LLM gets its context

An LLM never sees raw data. It sees an evidence pack, a compact deterministic summary with the numbers already computed and every item cited by id. Prompts are built in three layers, most stable first, so the expensive part is read from cache.

LLD · agent memory, borrowed from Hindsight

The desk's experience memory is built on our own PostgreSQL, borrowing the parts of Hindsight's architecture that fit: typed memories, consolidated observations with evidence, standing knowledge pages, and four-way retrieval. The difference is that every read is as of knowledge time, so a replay sees exactly the beliefs the desk held at the time, and structured facts never become memories.

Memory typeWhat it holdsWritten byRead by
World memoryA durable qualitative fact about a company, sector, market or sourceanalysts, head trader, humansrecall at decision time

ObservationA belief consolidated from several memories, with evidence ids, a proof count and a version chain by known_atnightly consolidationrecall, page rebuilds

DirectiveA rule a human gave the desk, highest trust, never consolidated awayhumansevery reader
Operations
  • remember: structured records stored verbatim; free text extracted by Haiku into memories with entities and times
  • recall(as_of): filter by known_at first, then four arms, rank fusion, rerank, pack to 800 tokens; no LLM
  • consolidate(scope): nightly on the Batch API; a contradiction is a new version that records the change
  • rebuild_pages(scope): only pages whose scope changed
  • reflect: weekly, Opus, in the review ritual
Replay and evaluationObservations and pages are versioned by known_at, so a replay at time T reads the beliefs the desk actually held at T with no rebuild. A backtest over a period the desk never traded starts with empty memory and fills it from the replayed journal. Every backtest and paper month runs twice, with memory and without, and the difference is reported. If memory does not pay for itself after costs, it stays evidence-only and does not feed conviction.

What a day costs

Estimates at the phase 3 to 5 scale: a core of 30 swing names, a daily intraday watchlist of 20, free-tier news volume. The naive design puts raw data in long prompts, uses Opus for everything, caches nothing and asks for prose.

Assumptions, re-check at signupOpus 5.5 at $4 per million input tokens, $20 per million output, cache reads $0.20 per million. Haiku 5.5 at $0.10 and $0.50, cache reads assumed at a tenth of input. Cache writes assumed at 1.25 times input. Batch API half price. Thinking tokens bill as output. Market data $0 until phase 5, then about $99 per month. One small VM at $20 to $40 per month. Replays about $0 through the output cache.
Levers, in the order they pay off
  1. evidence packs and structured outputs
  2. prompt caching with stable prefixes
  3. Haiku for bulk work, Opus for judgment
  4. Batch API overnight
  5. output cache by prompt hash
  6. effort tuned per route
  7. per-route daily call budgets with alerts; the head trader is the first budget we set
